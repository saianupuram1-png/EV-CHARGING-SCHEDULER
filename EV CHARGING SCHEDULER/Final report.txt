# 2. ABSTRACT & INTRODUCTION

## 2.1 Abstract

The increasing adoption of Electric Vehicles (EVs) has created a growing demand for efficient charging infrastructure. When multiple vehicles request charging at the same time, limited charging stations can create scheduling conflicts, delays and inefficient utilization of available charging slots.

The **EV Charging Slot Scheduler** is an algorithm-based system designed to assign charging slots to electric vehicles according to their urgency, arrival time, departure deadline and required charging duration.

The system uses three important Design and Analysis of Algorithms concepts: **Priority Queue, Greedy Algorithm and Job Sequencing**. The Priority Queue determines which vehicle should be considered first. The Greedy Algorithm selects the earliest feasible charging slot for each vehicle. Job Sequencing and deadline checking ensure that a vehicle is scheduled only when its charging can be completed before its departure deadline.

The project is implemented using Python and Flask, with PostgreSQL planned for persistent data storage. The system provides a user interface for entering vehicle requests and displays the resulting charging schedule along with algorithm execution details.

The project demonstrates how algorithmic techniques can be applied to a practical scheduling problem while making the decision-making process visible to users.

---

## 2.2 Introduction

Electric Vehicles are becoming an important part of modern transportation. Unlike conventional vehicles, EVs require periodic charging, which creates a need for efficient management of charging infrastructure.

A charging station may have only a limited number of charging slots. If several vehicles arrive simultaneously, the system must determine:

* Which vehicle should be charged first?
* Which charging slot should be assigned?
* Can the vehicle finish charging before its departure?
* How can available charging slots be utilized efficiently?

Manual scheduling becomes difficult when the number of vehicles increases. Therefore, an automated algorithmic solution can help organize charging requests.

The proposed system accepts information about each vehicle, including its urgency, arrival time, departure time and charging duration. It then processes the vehicles using a Priority Queue and assigns feasible slots using a Greedy strategy.

---

## 2.3 Proposed Solution

The proposed system follows three major algorithmic stages:

### Stage 1 — Priority Queue

Vehicles are placed into a priority queue according to:

1. Higher urgency
2. Earlier departure time
3. Shorter charging duration

### Stage 2 — Greedy Slot Selection

For each selected vehicle, the system checks the available charging slots and chooses the earliest feasible start time while ensuring:

**Charging End Time ≤ Departure Deadline**

### Stage 3 — Job Sequencing / Deadline Checking

If a vehicle can be completed before its deadline, it is scheduled.

If no feasible slot exists, the vehicle is marked:

**Not Scheduled**

This makes the scheduling decision transparent and algorithm-driven.

# 5.2 Algorithms Used

## Algorithm 1 — Priority Queue

The Priority Queue determines the order in which vehicles are processed.

Priority is based on:

1. Higher urgency
2. Earlier departure
3. Shorter charging duration

A priority value is calculated for each vehicle.

The vehicle with the highest priority is removed from the queue first.

### Example

Suppose:

| Vehicle | Urgency | Departure |
| ------- | ------: | --------- |
| EV001   |       5 | 10:00     |
| EV002   |       3 | 12:00     |
| EV003   |       5 | 09:30     |

EV003 is processed before EV001 because both have urgency 5, but EV003 has the earlier departure deadline.

---

# 5.3 Algorithm 2 — Greedy Algorithm

The Greedy Algorithm attempts to make the best locally feasible decision for each vehicle.

For every selected vehicle:

1. Check every charging slot.
2. Calculate the earliest possible start time.
3. Calculate the charging end time.
4. Verify that the end time is before the deadline.
5. Among feasible slots, select the one with the earliest start time.

The condition is:

```text
End Time = Start Time + Charging Duration

End Time ≤ Departure Time
```

This approach makes a locally feasible scheduling decision for every vehicle processed.

---

# 5.4 Algorithm 3 — Job Sequencing / Deadline Checking

The project applies job sequencing principles by treating each charging request as a job with:

* Processing time = charging duration
* Deadline = vehicle departure time
* Priority = urgency/deadline-based priority

A vehicle is scheduled only when a feasible slot can complete the charging before its deadline.

If no feasible slot is found:

```text
Status = Not Scheduled
```

---

# 5.5 Pseudocode

```text
START

Input vehicle requests

FOR each vehicle
    Calculate priority
    Insert vehicle into Priority Queue
END FOR

Initialize charging slots

WHILE Priority Queue is not empty

    Remove highest-priority vehicle

    best_slot = NONE

    FOR each charging slot

        start = maximum(arrival time, slot available time)

        end = start + charging duration

        IF end <= departure deadline

            IF start is earlier than current best start
                Select this slot
            END IF

        END IF

    END FOR

    IF a feasible slot exists

        Assign vehicle to selected slot
        Update slot availability
        Mark vehicle as Scheduled

    ELSE

        Mark vehicle as Not Scheduled

    END IF

END WHILE

Display final schedule
Display algorithm execution log

END
```

# 6.5 Implementation Details

The main data structure used for scheduling is Python's heap-based Priority Queue.

A vehicle is represented using a data class:

```python
@dataclass
class Vehicle:
    vehicle_id: str
    urgency: int
    arrival: int
    departure: int
    duration: int
```

Time values are converted into minutes to simplify scheduling calculations.

For example:

```text
08:00 → 480 minutes
09:30 → 570 minutes
```

After scheduling, the minutes are converted back into `HH:MM` format for display.

The system maintains the availability of each charging slot using:

```python
slot_available = [0] * number_of_slots
```

For three charging slots:

```text
Slot 1
Slot 2
Slot 3
```

each slot maintains its next available charging time.

# 7.5 Performance Analysis

Let:

* `n` = number of vehicles
* `k` = number of charging slots

### Priority Queue

Insertion/removal from a heap takes:

```text
O(log n)
```

For `n` vehicles:

```text
O(n log n)
```

### Greedy Slot Selection

Each vehicle checks all `k` slots:

```text
O(k)
```

For `n` vehicles:

```text
O(nk)
```

### Overall Complexity

The approximate overall time complexity is:

```text
O(n log n + nk)
```

### Space Complexity

The main data structures require approximately:

```text
O(n + k)
```

space.

The algorithm therefore remains practical for a moderate number of vehicles and charging slots.
